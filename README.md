## Как получены результаты

Данные сгенерированы штатным `make_dataset.py --student 7`. Отчёт выполнен в ядре Jupyter. PostgreSQL 16.2, Airflow 2.11.0 (LocalExecutor) и MLflow 3.16.1 работали отдельными процессами. Для S3 использован сетевой S3-совместимый тестовый сервер Moto. **Docker/RustFS в этой среде не запускались.** Настроенный Compose оставлен для воспроизведения на компьютере с Docker; использованные в учебном стеке общие пароли не подходят для публичного развёртывания.

## Если нужно повторить, а не просто сдать

1. Распаковать архив с сохранением каталогов. В `data-stack` выполнить `docker compose build`, затем `docker compose up -d`. Убедиться через `docker compose ps`, что инициализация завершилась, остальные сервисы готовы. Подробнее об установке — `INSTALL.md`.
2. Открыть `http://localhost:8888` → `work/students/user1/project_report_7.ipynb` → **Run All**. Исходный CSV, генератор и DAG-файлы уже на месте. Пользователь Jupyter должен иметь право записи в `work` и `dags` (на Linux — UID 1000 в исходном образе). Чтобы сохранить первоначальные outputs, работать с копией архива.
3. В Airflow (`localhost:8080`, `student/student`) выбрать `user1_p7_churn`; в MLflow (`localhost:5001`) — эксперимент `user1_p7_churn`, реестр `user1_p7_model`. Запуски проекта инициируются из ноутбука. Параметры случайного сбоя фиксированы заданием, **число попыток при новом прогоне может отличаться**. При существующем чемпионе равный результат не создаёт новую версию.
4. Практикумы можно запускать независимо в Jupyter. Ноутбук 03 пишет DAG в общую папку, включает расписание heartbeat и после наблюдения ставит его на паузу. Сохранённые результаты относятся к отдельному учебному стеку, не к пустым Docker volumes после установки.
5. `docker compose down` останавливает стек и сохраняет volumes. Не добавлять `-v`, если нужны история или артефакты.

**Независимая проверка без сервисов** (Python 3.11, из корня распакованного архива): установить `data-stack/work/students/user1/evidence/champion/requirements.txt`, затем `python tools/check_submission.py`. Проверка загружает локальную модель, пересчитывает обе метрики и все 100 записей выдачи, проверяет паспорт и отсутствие ошибок в сохранённых ноутбуках.
