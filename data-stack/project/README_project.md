# ИТОГОВЫЙ ПРОЕКТ. «Отток клиентов телеком-оператора»: от данных до работающего конвейера

Вы — младший ML-инженер в виртуальном операторе связи «TeleData».
Каждый месяц компания теряет клиентов, и каждый ушедший — это потерянная выручка.
Ваш задача — построить **работающую систему**, которая по данным о клиентах
предсказывает вероятность ухода и сама обновляется по кнопке/расписанию:
данные → подготовка → обучение нескольких моделей → выбор лучшей → реестр →
список клиентов группы риска.

Проект использует **все инструменты курса**: S3, PostgreSQL, MLflow, Airflow —
на **вашем собственном компьютере в Docker**.

**Срок: 2 недели. Сдаётся: ноутбук-отчёт с результатами + файл DAG + датасет.**

---

## Ваш персональный вариант (защита от списывания)

У каждого студента **свой датасет и свои параметры** — они определяются номером
по журналу `N`. Числа в отчёте у соседей будут другие: другой процент оттока,
другие метрики, другая лучшая модель. **Совпавший «паспорт» датасета у двух
студентов = 0 баллов обоим.**

| Параметр | Формула по вашему N |
|---|---|
| датасет | `python make_dataset.py --student N` → `customers_N.csv` |
| размер теста | `N % 3 == 0 → 0.20`, `N % 3 == 1 → 0.25`, `N % 3 == 2 → 0.30` |
| дополнительная модель (сверх 4 обязательных) | `N % 4 == 0 → HistGradientBoostingClassifier`, `1 → SVC(probability=True)`, `2 → GaussianNB`, `3 → ExtraTreesClassifier` |
| главная метрика выбора модели | `N чётное → roc_auc`, `N нечётное → average_precision (PR-AUC)` |
| вероятность сбоя ненадёжной задачи в DAG | `p = 0.25 + 0.10 * (N % 3)` |
| порог ворот качества | метрика текущего чемпиона `+ 0.01` |

Посчитайте свои значения **до начала работы** и впишите в ячейку «Паспорт» отчёта.

## Часть 4. Обучение и сравнение моделей в MLflow (4 балла)

1. Эксперимент `user1_p{N}_churn`. Обучите **4 обязательные модели**
   (LogisticRegression, RandomForest, DecisionTree, KNN) + **1 модель по варианту**.
   У каждой — минимум **3 значения** хотя бы одного гиперпараметра
   (итого ≥ 15 запусков; считаются по таблице эксперимента).
2. В каждом запуске: параметры, `roc_auc` и `average_precision` на тесте,
   модель (`mlflow.sklearn.log_model`). Для лучшей модели — артефакты:
   матрица ошибок, ROC-кривая, PR-кривая, важность признаков.
3. Таблица сравнения всех запусков (`search_runs`, сортировка по **вашей** метрике
   из паспорта) — в отчёт.
4. Лучшая модель → реестр `user1_p{N}_model` с меткой `@champion`.
   Затем обучите «претендента» (измените сильный гиперпараметр) и выполните
   **ворота качества**: метка переезжает, только если претендент лучше
   порога из паспорта. Оба исхода (переезд/отказ) покажите в отчёте.

## Часть 5. Конвейер в Airflow (5 баллов)

Возьмите `dag_template.py`, переименуйте в `user1_p{N}_churn.py`, заполните TODO
и положите в папку `dags`. Требования к DAG:

```
load_raw (НЕНАДЁЖНАЯ: падает с вероятностью p, retries=6)   ← здесь вы покажете повторы
   └─> prepare (чистка, train/test parquet → S3)
         └─> train × 4-5 (ПАРАЛЛЕЛЬНО, каждая пишет запуск в MLflow)
               └─> select_best (по вашей метрике)
                     └─> quality_gate (сравнение с чемпионом)
                           └─> register_champion (только если прошла ворота)
                                 └─> top_risk (top-100 клиентов по вероятности ухода
                                      → CSV в S3 + таблица в PostgreSQL)
```

- Задача `load_raw` **должна упасть и перезапуститься**: добейтесь, чтобы в Grid
  была оранжевая попытка (`up_for_retry`), а запуск в итоге дошёл до зелёного
  конца. Вероятность сбоя — из паспорта. Итоговое число попыток покажите в отчёте.
- Всё, что передаётся между задачами — **ключи S3 и маленькие словари** (XCom),
  не датасеты.
- Запустите DAG **минимум дважды**: первый — выпуск чемпиона, второй — проверка
  ворот (метка должна вести себя разумно, объясните в отчёте).
